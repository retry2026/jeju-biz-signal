# PRD — 제품 요구사항

버전 1.0 · 2026-11-13 · 기준 문서: `docs/IDEA.md`

## 1. 목표

| 목표 | 측정 방법 | 목표값 |
|---|---|---|
| 데이터로 답할 수 있는 질문에 정확한 숫자로 답한다 | 평가 세트 수치 정확도 | 90% 이상 |
| 데이터에 없는 질문은 거절하고 대안을 제시한다 | 평가 세트 거절 정확도 | 100% (5/5) |
| 필요한 도구를 고른다 | 평가 세트 도구 선택 정확도 | 80% 이상 |
| 답에 근거와 한계가 붙는다 | 응답에 `evidence`, `limits`가 있는 비율 | 100% (ANSWER) |
| 비전문가가 쓸 수 있다 | 처음 쓰는 팀원이 안내 없이 시나리오 B를 끝까지 실행 | 성공 |

목표값은 11/16 평가 1차 뒤 현실적으로 조정할 수 있다.

## 2. 사용자와 상황

## 3. 사용자 스토리

| ID | 스토리 | 우선순위 |
|---|---|---|
| US-1 | U1로서 동네와 업종을 고르고 "괜찮을까요?"라고 물으면, 경쟁 점포 수와 손님 구성을 보고 싶다 | P0 |
| US-2 | U2로서 "겨울만 되면 매출이 줄어요"라고 물으면, 그게 동네와 업종의 구조인지 알고 싶다 | **P0 (간판)** |
| US-3 | U2로서 내 월매출을 넣으면, 동네 흐름과 관광객 흐름에 비해 내 가게가 어떤지 알고 싶다 | P1 |
| US-4 | 누구든 데이터에 없는 것을 물으면, 왜 안 되는지와 대신 볼 수 있는 것을 알고 싶다 | P0 |
| US-5 | 누구든 답의 숫자가 어디서 왔고 언제 기준인지 알고 싶다 | P0 |
| US-6 | 누구든 두 동네를 비교해 달라고 하면 같은 기준으로 비교해 보고 싶다 | P1 |
| US-7 | 다음 사용자를 위해, 내가 자리를 떠나면 화면이 처음으로 돌아갔으면 한다 | P0 |

P0은 11/16까지, P1은 11/17까지. P1은 일정이 밀리면 뺀다.

## 4. 기능 요구사항

### 입력

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 사용자 유형(예비 창업자, 기존 사업자)을 버튼으로 고른다 | P0 |
| FR-02 | 지역(읍면동 43개)을 드롭다운으로, 업종(외식업 7개)을 버튼으로 고른다 | P0 |
| FR-03 | 질문은 채팅으로 입력한다 (1~500자) | P0 |
| FR-04 | 사용자 유형별 예시 질문 버튼을 보여준다. 누르면 그 문장으로 질문한다 | P0 |
| FR-05 | 기존 사업자는 최근 월매출을 입력할 수 있다 (선택, 1~12개월) | P1 |

### 에이전트 판단

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 지역, 업종, 질문 중 하나라도 비면 LLM을 부르지 않고 되묻는다 (`ASK_BACK`) | P0 |
| FR-11 | 질문을 답변 / 거절 / 되묻기로 분류한다 | P0 |
| FR-12 | 질문에 맞는 도구(`competition`, `areaCustomers`, `industryTourism`)를 골라 부른다. 여러 개를 조합할 수 있다 | P0 |
| FR-13 | 도구 결과가 표본 부족이면 기간을 12개월에서 24개월로 넓혀 다시 부르고, 그 사실을 알린다 | P1 |
| FR-14 | 매출 하락 질문에는 전년 대비와 최근 관광 흐름 비교를 스스로 덧붙인다 | P1 |
| FR-15 | 두 동네 비교 질문이면 같은 도구를 동네마다 부른다 | P1 |
| FR-16 | 같은 세션 안에서는 앞 질문을 기억하고 후속 질문에 답한다 | P1 |
| FR-17 | 월매출이 필요한 질문인데 입력이 없으면 입력을 요청한다 (`ASK_BACK`, `askFor=MY_STORE`) | P1 |

### 답변

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 한두 문장 결론(`summary`)과 섹션별 본문을 준다 | P0 |
| FR-21 | 본문의 모든 숫자는 도구 결과에 있는 값이다. LLM이 숫자를 만들지 않는다 | P0 |
| FR-22 | 차트를 0~3개 붙인다. 차트 데이터는 코드가 도구 결과로 만든다 | P0 |
| FR-23 | 실제로 쓴 데이터의 출처, 기간, 기준(동네/제주 전체)을 표시한다 (`evidence`) | P0 |
| FR-24 | 한계 문구를 붙인다 (`limits`). 최소: 기준 단위, 카드 데이터 원천, "예측이 아님" | P0 |
| FR-25 | "데이터가 보여주는 것"과 "고려해 볼 점"을 나눠 쓴다 | P0 |
| FR-26 | 다음 질문 제안을 0~3개 버튼으로 보여준다 | P1 |
| FR-27 | 지역 순위나 "위험 지역" 같은 라벨을 만들지 않는다 | P0 |

### 거절해야 하는 질문 (FR-30)

| 질문 유형 | 이유 | 대신 제안 |
|---|---|---|
| 시간대 ("저녁 장사 어때요?") | 시간대 데이터 없음 | 손님 구성, 계절 흐름 |
| 예상매출 ("여기 월매출 얼마 나와요?") | 위치별 매출 추정 안 함 | 동네 손님 구성 |
| 개별 가게 ("옆집 매출 얼마예요?") | 개별 가게 데이터 없음, 제공 불가 | 동네 평균 흐름 |
| 폐업 예측 ("이 가게 망할까요?") | 예측하지 않음 | 상권 흐름과 비교한 현재 상태 |
| 임대료, 소득, 배달, 유동인구 | 데이터 없음 | 가능한 분석 |

| FR-44 | 2분 동안 조작이 없으면 처음 화면으로, 세션 새로 | P0 |
| FR-45 | 키오스크용 큰 글씨, 큰 버튼 | P0 |
| FR-46 | 화면 하단에 데이터 기준일 표시 | P1 |

## 5. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-01 | 실행은 `java -jar` 한 줄. Docker, DB 서버, 별도 프론트 서버 없음 |
| NFR-02 | 센터 PC 최소사양(i7-8700, GTX 1060, RAM 32GB)에서 동작 |
| NFR-03 | 응답 시간 대부분 30초 이내 |
| NFR-04 | 외부 호출은 LLM API 하나. 데이터는 로컬 파일 |
| NFR-05 | API 키는 환경변수로만. 제출물에 키 없음 |
| NFR-06 | README대로 다른 PC에서 처음부터 설치·실행 가능 (재현성) |
| NFR-07 | 개인정보, 개별 가게 매출을 다루지 않는다 |

## 6. 범위 밖

예상매출 추정, 시간대 분석, 폐업 예측, 유동인구, 임대료, 외식업 외 업종, 로그인, 관리자 화면, 모바일 앱, 다국어.
